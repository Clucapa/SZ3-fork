# 复合函数 & 多 QoI 组合 — 实现计划

## 动机

将 `int qoi` 改为十六进制 nibble 编码，用 `F` 分隔符实现组内求和（SumQoI）和多组 AND 约束（MultiQoI），替代 QoZ 的 MultiQoIs + XComposite 两套语义。同时把 `QpetBlockDecomp` 中硬编码的 QoI → Provider 映射改为虚函数。

## int qoi 编码方案

`int qoi` 从低位到高位，每 4 bit 一格。编码表：

| 编码 | 含义 |
|------|------|
| `0x0` | XLin (f(x)=x) |
| `0x1` | XSquare (f(x)=x²) |
| `0x2` | XCubic (f(x)=x³) |
| `0x3` | XSqrt (f(x)=√x) |
| `0x4` | XExp (f(x)=aˣ) |
| `0x5` | XLogX (f(x)=x·ln x) |
| `0x6` | LogX (f(x)=log_a x) |
| `0x7` | XRecip (f(x)=1/x) |
| `0x8` | XAbs (f(x)=​|x|) |
| `0x9` | XSin (f(x)=sin x) |
| `0xA` | XTanh (f(x)=tanh x) |
| `0xB` | XPower (f(x)=x^a) |
| `0xC~0xE` | 预留 |
| `0xF` | **组分隔符** |

用途：

| 编码 | 含义 |
|------|------|
| `0x1` | XSquare 单独约束 |
| `0x12` | XSquare + XCubic 求和约束 |
| `0x1F3` | XSquare AND XSqrt |
| `0x12F3F456` | Sum(1,2) AND 3 AND Sum(4,5,6) |

**Regional**：将 regional 编号做 `~` 翻转存入 `conf.qoi`，最高位为 1 触发 regional 路径。Regional 编号独立（0=RegionalMean, 1=RegionalMeanSq, 2=RegionalAvgInterp, 3=RegionalMeanSqInterp），与 pointwise nibble 编号空间分离。`is_pointwise()` 改为 `return id >= 0;`，无需子类逐个重写。

## 核心设计

### 接口改动

在 `QoIIf` 基类新增：

```cpp
template <class T, uint N>
class QoIIf {
public:
    // ... 现有方法 ...

    virtual std::unique_ptr<concepts::EBProvider<T>> create_eb_provider(
        const Config &conf) = 0;

    // 正向求值 f(x)。默认返回 x（恒等）
    virtual double eval(T val) const { return static_cast<double>(val); }

    int id = 0;
};
```

**不加** `derivative(T val)`（用数值导数 `(eval(x+h)-eval(x-h))/(2h)` 逼近）。**不加** `set_qoi_tolerance`（没有 f∘g 反向传播需求）。

### QpetBlockDecomp 简化

硬编码映射替换为：

```cpp
// 旧 — 删除
if (qoi->id == 10) {
    eb_provider = std::make_unique<RegionalMeanEBProvider>(...);
} else if ...

// 新 — 一行
auto eb_provider = qoi->create_eb_provider(conf);
```

### Layer 架构

```
Layer 0 (零 SZ3 依赖)
├── QoIIf<T,N>           — QoI 算法接口
│   + create_eb_provider()
│   + eval(T val)
└── EBProvider<T>        — eb 源统一读取接口

Layer 1 (继承 Layer 0)
├── 基础函数 (XLin, XSquare, ... 13 种)
├── SumQoI<T,N>          — 组内求和约束（由 nibble 编码驱动）
├── MultiQoI<T,N>        — 多组 AND 约束（由 F 分隔符驱动）
├── PointwiseEBProvider
├── MultiQoIEBProvider   — 持有多个子 Provider，advance 取 min
└── Regional(Mean/MeanSq)EBProvider
```

## SumQoI（组内求和）

由 nibble 编码解析后组装。持有多个基础函数实例。

```cpp
template <class T, uint N>
class QoI_SumQoI : public concepts::QoIIf<T, N> {
public:
    QoI_SumQoI(std::vector<std::shared_ptr<QoIIf<T, N>>> funcs,
               double tol, T geb);

    T interpret_eb(T x) const override {
        double sum_deriv = 0;
        for (auto &f : funcs_) {
            double h = std::max(1e-6, 1e-4 * fabs(x));
            sum_deriv += (f->eval(static_cast<T>(x + h)) - 
                          f->eval(static_cast<T>(x - h))) / (2 * h);
        }
        T eb = tol_ / fabs(static_cast<T>(sum_deriv));
        return std::min(eb, geb_);
    }

    bool check_comply(T orig, T dec) const override {
        return fabs(eval(orig) - eval(dec)) <= tol_;
    }

    double eval(T val) const override {
        double s = 0;
        for (auto &f : funcs_) s += f->eval(val);
        return s;
    }

    // Pointwise — 用 PointwiseEBProvider
    std::unique_ptr<EBProvider<T>> create_eb_provider(
            const Config &conf) override {
        return std::make_unique<PointwiseEBProvider<T>>(
            conf.ebs.data(), conf.ebs.size());
    }

private:
    std::vector<std::shared_ptr<QoIIf<T, N>>> funcs_;
    double tol_;
    T geb_;
};
```

## MultiQoI（多组 AND 约束）

由多个 F 分隔符触发的多组组合。持有一组 SumQoI（含单函数组）。

```cpp
template <class T, uint N>
class QoI_MultiQoI : public concepts::QoIIf<T, N> {
public:
    QoI_MultiQoI(std::vector<std::shared_ptr<QoIIf<T, N>>> groups,
                 std::vector<double> tolerances);

    T interpret_eb(T x) const override {
        T eb = groups_[0]->interpret_eb(x);
        for (size_t i = 1; i < groups_.size(); ++i)
            eb = std::min(eb, groups_[i]->interpret_eb(x));
        return eb;
    }

    bool check_comply(T orig, T dec) const override {
        for (auto &g : groups_)
            if (!g->check_comply(orig, dec)) return false;
        return true;
    }

    double eval(T val) const override;  // 无意义，返回 val

    std::unique_ptr<EBProvider<T>> create_eb_provider(
            const Config &conf) override;  // → MultiQoIEBProvider
};
```

### MultiQoIEBProvider

```cpp
template <typename T>
class MultiQoIEBProvider : public concepts::EBProvider<T> {
public:
    MultiQoIEBProvider(std::vector<std::unique_ptr<EBProvider<T>>> providers);

    T advance(T orig, T dec) override {
        T eb = providers_[0]->advance(orig, dec);
        for (size_t i = 1; i < providers_.size(); ++i)
            eb = std::min(eb, providers_[i]->advance(orig, dec));
        return eb;
    }

    void advance() override {
        for (auto &p : providers_) p->advance();
    }

    // precompress_block, postcompress_block, reset, save, load 逐层委托
};
```

## Nibble 编码解析器

工厂新增 `parse_qoi_nibbles(int qoi)` 函数：

```cpp
struct QoIGroup {
    std::vector<int> func_ids;          // 组内函数 ID 列表
    double tol = 0;                     // 来自 qoiEBs 或 qEB
};

std::vector<QoIGroup> parse_qoi_nibbles(int qoi) {
    std::vector<QoIGroup> groups;
    QoIGroup cur;
    while (qoi) {
        int nib = qoi & 0xF;
        qoi >>= 4;
        if (nib == 0xF) {
            if (!cur.func_ids.empty()) {
                groups.push_back(cur);
                cur = QoIGroup{};
            }
        } else if (nib >= 0x0 && nib <= 0xD) {
            cur.func_ids.push_back(nib);
        } else {
            throw std::invalid_argument("Unknown nibble: " + std::to_string(nib));
        }
    }
    if (!cur.func_ids.empty()) groups.push_back(cur);
    return groups;
}
```

解析逻辑：
1. 从低位逐个读 nibble
2. 遇到 0xF 结束当前组，新建下一组
3. 遇到 0x0~0xD 加入当前组
4. 满一个组后关联 `conf.qoiEBs[i]` 的 tolerance

## Regional QoI 路径

最高位置 1 触发 regional 路径。函数编码相同，但不走 PointwiseEBProvider + ebs[] 预计算。各组内部走 budget tracking（自己维护 `precompress_block` / `update_tolerance` 的内部状态）。多组 AND 下各组各自维护 budget，组内和约束直接使用 `eval(orig) - eval(dec)` 更新 shared 误差。

Regional 版的 interpret_eb 同样用数值导数推 eb（逻辑不变，改从 budget 剩余预算算 eb 而非固定 τ）。

如果组内含 regional 专用逻辑（需要跟踪跨点状态），则用 Regional 同款 EBProvider（预算更新型），否则用 Pointwise EBProvider（预计算型）。目前 Regional 路径仅针对需预算的组合（如区域平均值/区域均方）。组合型函数第一次用 regional 路径时直接用现有的 `RegionalMean/RegionalMeanSq` 的模式——regional 版 SumQoI 内部维护 budget，eb 从剩余预算 + 导数推。

## 风险

- 数值导数对不光滑函数（如 |x|）在 x=0 处不稳定。对于不可导函数，需要在基础函数里提供解析导数或特殊的 interpret_eb 公式（不依赖 eval 差值）
- 多组 AND 下各组 tolerance 独立分配（`qoiEBs` 数组），用户需要了解各函数对 τ 的相对敏感度
- Regional 路径的组合函数需验证 budget tracking 的数值稳定性（多组共享 `error` 累加器可能溢出）
